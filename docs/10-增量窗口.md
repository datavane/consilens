# 增量窗口与 checkpoint

`diff` 支持按时间/单调列做增量窗口，并可把本次窗口上界写入 watermark 文件，供下一次运行作为下界。它只复用现有 `PredicateSpec` 过滤能力，不改变执行引擎。

## 一、命令

```bash
consilens-cli.sh diff \
  -c compare.yaml \
  --window-column updated_at \
  --window-from "2026-01-01 00:00:00" \
  --window-to "2026-02-01 00:00:00"
```

带 checkpoint 的周期运行：

```bash
consilens-cli.sh diff \
  -c compare.yaml \
  --window-column updated_at \
  --window-to "2026-02-01 00:00:00" \
  --checkpoint-file .consilens/watermark.txt
```

首次运行读取窗口 `>= window-from`（未提供则不设下界）且 `< window-to`；成功后把 `window-to` 写入 checkpoint。下一次运行读取 checkpoint 作为 `from`，只比较新窗口。

`verify` 复用同一组窗口参数：

```bash
consilens-cli.sh verify -c compare.yaml \
  --window-column updated_at \
  --window-to "2026-02-01 00:00:00" \
  --checkpoint-file .consilens/verify-watermark.txt \
  --fail-on any
```

`verify` 只在 verdict=`PASS` 时推进 checkpoint；`FAIL`/`INCONCLUSIVE`/`BUDGET_EXCEEDED` 都不推进，下一次会重试同一窗口。

## 二、语义

- 下界包含、上界不包含：`column >= from AND column < to`。
- 两侧默认使用同一列；列名不同时用 `--source-window-column` / `--target-window-column`。
- 窗口与已有 `comparison.filters` 合并：`(existing) AND (window)`。
- 值按 SQL 字符串字面量引用，单引号会转义；日期/时间戳按数据库方言的隐式转换处理。
- checkpoint 只在比对成功返回后推进；差异数量不影响推进，失败/异常不推进。
- `--dry-run` 不推进 checkpoint。

## 三、限制

- 仅支持 JDBC 源。文件连接器不应用 SQL 谓词，命令会直接报错，避免窗口被静默忽略。
- 不支持 `comparison.mappings`；窗口列必须是物理列名。
- 窗口列需要可比较且在两侧同语义；跨时区时间戳需自行保证数据库会话时区一致。
- 不处理迟到数据/重叠窗口；需要重跑时删除或回退 checkpoint，或显式提供 `--window-from`。
- `metrics` 暂不支持窗口参数。

## 四、退出码

- `diff`：`0` 成功（**有差异也是 0**）；`1` 执行/参数错误；`2` 仅当加了 `--fail-on-diff` 且确实发现差异。
- `verify`：沿用自身契约 `0` PASS、`1` FAIL、`2` ERROR、`3` INCONCLUSIVE、`4` BUDGET_EXCEEDED；只有 PASS 推进 checkpoint。

> ⚠️ 窗口相关的参数错误是 **`1`**，不是 `2`。实测（真实 MySQL）：
> 文件源 + 窗口 → `1`（`window requires a JDBC source; file sources do not apply SQL filters`）、
> `--window-from` 缺少 `--window-column` → `1`、窗口列写错 → `1`（SQL 报 `Unknown column`）、
> `comparison.mappings` 冲突 → `1`。`diff` 的完整码表见 [CI 集成](./07-CI集成.md#diff-的退出码与-verify-不同)，
> 与 `verify` 的 `1`/`2` 含义相反，不要混用。
