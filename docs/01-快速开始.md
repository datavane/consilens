# 快速开始

## 适用对象

本文适合第一次使用 Consilens 的用户，目标是在最短时间内完成一次跨数据源数据比对。

## 环境要求

- JDK 11 及以上
- 可访问源数据源和目标数据源的网络
- 两侧数据集都能通过主键唯一定位
- 建议预留 4G 以上可用内存；超大表比对建议 8G 以上

启动脚本默认使用 `-Xmx4g -Xms256m`。需要更大堆时覆盖 `JAVA_OPTS`：

```bash
JAVA_OPTS="-Xmx8g -Xms512m" ./bin/consilens-cli.sh diff -c config.yaml
```

## 构建

在仓库根目录执行：

```bash
./mvnw -B clean package -Prelease
```

产物位置：

- consilens-dist/target/consilens-${version}.tar.gz

## 解压运行

```bash
tar -xzf consilens-dist/target/consilens-${version}.tar.gz
cd consilens-${version}
./bin/consilens-cli.sh --help
```

发行包结构：

- `bin/`：启动脚本与环境变量脚本
- `conf/`：日志配置
- `libs/`：CLI 与核心依赖
- `plugins/`：连接器插件与 JDBC 驱动
- `examples/`：打包时拷入的示例配置
- `logs/`：运行日志

## 最小可用配置

```yaml
source:
  type: mysql
  connection:
    url: jdbc:mysql://localhost:3306/source_db
    username: source_user
    password: change_me_source_password
  resource:
    type: table
    name: orders

target:
  type: postgresql
  connection:
    url: jdbc:postgresql://localhost:5432/target_db?currentSchema=public
    username: target_user
    password: change_me_target_password
  resource:
    type: table
    name: orders

comparison:
  keys:
    source:
      - order_id
    target:
      - order_id
  fields:
    source:
      - order_id
      - customer_id
      - amount
      - status
      - created_at
    target:
      - order_id
      - customer_id
      - amount
      - status
      - created_at

strategy:
  mode: checksum
  algorithm: xor
  bisectionFactor: 8
  bisectionThreshold: 5000
  batchSize: 1000
  localCompare:
    mode: full

result:
  sinks:
    - format: console
      type: result
    - format: json
      type: diff-record
      properties:
        path: ./diff_results.json
        pretty: true
```

说明：

- `source.type` / `target.type` 可省略；省略时根据 JDBC URL 自动识别。
- `connection` 中配置数据源连接参数，`resource` 指定要比对的数据集（如表名）。
- `comparison.keys` 两侧主键列数量必须一致。
- `comparison.fields` 是实际参与数据比较的字段，通常应包含主键列。

## 执行比对

```bash
./bin/consilens-cli.sh config validate -c config.yaml
./bin/consilens-cli.sh diff -c config.yaml
```

`diff` 默认即使发现差异也返回 0。需要在脚本中把差异当作失败时加 `--fail-on-diff`（有差异返回 2）。

### CI 门禁

```bash
./bin/consilens-cli.sh verify -c config.yaml \
  --fail-on any \
  --format junit,markdown \
  --output-dir consilens-reports
```

退出码：0 PASS、1 FAIL、2 ERROR、3 INCONCLUSIVE、4 BUDGET_EXCEEDED。详见 [CI 集成](./07-CI集成.md)。

### 本地文件

CSV/JSONL/Parquet 使用 `type: file`，无需 JDBC：

```yaml
source:
  type: file
  name: source
  resource:
    type: file
    path: ./data/source.csv
    format: csv
target:
  type: file
  name: target
  resource:
    type: file
    path: ./data/target.csv
    format: csv
comparison:
  keys: {source: [id], target: [id]}
  fields: {source: [name, amount], target: [name, amount]}
```

目录/glob、S3、Parquet、Iceberg 见 [连接器与数据源](./03-插件与数据库支持.md)。

### 其他入口

```bash
# 指标聚合/分组（Java 或 DuckDB 引擎）
./bin/consilens-cli.sh metrics -c config.yaml --metric count --metric sum:amount

# 契约比较与配置骨架
./bin/consilens-cli.sh contract diff -s a.odcs.yaml -t b.yml --format markdown
./bin/consilens-cli.sh contract init -s a.odcs.yaml -t b.yml \
  --source-type mysql --target-type postgresql -o compare.yaml

# 连接器 SPI 认证
./bin/consilens-cli.sh connector certify -c config.yaml
```

请先把 `config.yaml` 中的用户名和密码替换为真实值。配置文件支持环境变量占位符，语法为 `${env.VAR_NAME}` 或 `${env.VAR_NAME:默认值}`，例如 `password: ${env.DB_PASSWORD:change_me}`。

## 结果解读

常见差异类型：

- `SOURCE_MISSING`：目标表存在，源表不存在
- `TARGET_MISSING`：源表存在，目标表不存在
- `MISMATCH`：主键相同，但非主键字段不一致

当开启 `infoTree` 输出时，可以看到每一段的：

- 行数
- 分裂方式
- checksum 是否一致
- 最终落到本地比较的段

## 使用建议

### 首次接入

- 先用一张小表验证配置正确性。
- 再放大到目标表。

### 大表

- 优先使用 `strategy=checksum`
- `algorithm` 推荐 `xor`
- 终局本地比较默认使用 `full`；只有确认宽表、低差异比例场景受益时，再显式配置 `localCompare.mode: row-hash`

### 同库同实例

- 可考虑 `strategy=join`
- `join` 仅支持两侧数据集位于同一个 JDBC URL

### 需要落库或写文件

- 在 `result.sinks[]` 中配置 `format: table` 类型 sink，并填写数据库连接参数
- 也可配置 `format: json` 或 `format: csv` 写出到文件
