# 连接器认证（connector certification）

`connector certify` 用一组与数据库无关的契约检查验证连接器实现：能否打开数据集、schema 是否完整、是否提供 `RecordScanner`、扫描是否确定、关闭是否安全。它不校验 SQL 方言细节或业务数据正确性，那些属于各连接器自己的集成测试。

## 一、命令行

```bash
consilens-cli.sh connector certify \
  -c compare.yaml \
  --side both \
  --max-rows 100 \
  --format markdown
```

| 选项 | 说明 |
| --- | --- |
| `-c, --config` | 现有比对配置；用其 source/target 连接配置 |
| `--side` | `source`、`target` 或 `both`（默认） |
| `--max-rows` | 每次扫描最多读取的行数，默认 100 |
| `--format` | `markdown`（默认）或 `json` |
| `-o, --output` | 写入文件；省略时输出到 stdout |

退出码：`0` 全部通过；`1` 存在失败检查；`2` 配置/参数错误。

报告包含每个 side 的连接器类型、资源名、实际读取行数，以及逐项检查结果。

## 二、检查项

| 检查 | 内容 |
| --- | --- |
| `provider-type` | provider 类型与配置 `type` 一致（忽略大小写） |
| `adapter.create` | `ConnectorProvider.create` 成功且返回非空 |
| `dataset.open` | `openDataset` 成功且返回非空 |
| `schema` | 字段非空、字段名/规范类型非空、ordinal 不重复 |
| `metadata` | `getMetadata()` 返回非空 |
| `record-scanner` | `getRecordScanner()` 提供 scanner |
| `scan` | 使用 schema 全列、配置 key、`OffsetLimitSplit(0, maxRows)` 扫描成功 |
| `scan.deterministic` | 连续两次扫描行数一致 |
| `close.*` | dataset 与 adapter 关闭不抛异常 |

扫描只检查每条记录 `values` 非空，不比对具体值；因此不会因数据差异误判连接器。

## 三、在测试中使用 testkit

第三方连接器可以依赖 `consilens-connector-testkit`：

```xml
<dependency>
  <groupId>com.consilens</groupId>
  <artifactId>consilens-connector-testkit</artifactId>
  <version>${consilens.version}</version>
  <scope>test</scope>
</dependency>
```

```java
CertificationReport report = ConnectorCertification.verify(
        new MyConnectorProvider(), connectorConfig,
        KeySpec.builder().fields(List.of("id")).build(), 100);
assertTrue(report.isPassed(), report.failures().toString());
```

`CertificationReport.failures()` 返回可直接放进断言消息的失败列表。

## 四、限制

- 检查的是 SPI 契约，不验证 checksum/row-hash 语义、SQL 方言、类型归一化精度。
- 需要真实可连接的数据源；CI 中可用容器或测试库注入配置。
- `maxRows` 是扫描上限，但部分 scanner 可能先完整物化再应用 split；大表上仍应使用小表或受限资源。
- 只支持通过现有配置构造连接参数，不提供交互式凭据输入。
