# 开发指南

本文面向项目维护者和插件开发者，说明如何在当前代码结构下开发、调试和扩展 Consilens。

## 一、开发环境

基础要求：

- JDK 11
- Maven 3.8+

推荐构建参数：

```bash
MAVEN_OPTS="-Xmx8g -Xms8g -DsocksProxyHost= -DsocksProxyPort= -Djava.net.useSystemProxies=false"
```

常用命令：

```bash
# 全量构建 + 测试（默认 JDK 11）
./mvnw -B package

# 单模块回归
./mvnw -B -pl consilens-core -am test

# 发行包（sources + dist）
./mvnw -B -Prelease -pl :consilens-dist -am package -DskipTests

# sources + Javadoc（需要 install，让 javadoc fork 解析 reactor 依赖）
./mvnw -B -Prelease,javadoc -pl :consilens-dist -am install -DskipTests

# MCP（JDK 17）
./mvnw -B -Pconsilens-mcp -pl consilens-mcp package
```

本地启动 server（默认 `mysql` profile，连接 `localhost:3306/consilens`）：

```bash
export CONSILENS_DB_USERNAME=root
export CONSILENS_DB_PASSWORD='<local-password>'
./mvnw -pl consilens-server -am spring-boot:run
```

没有本地 MySQL 时可用内嵌 H2：

```bash
SPRING_PROFILES_ACTIVE=local ./mvnw -pl consilens-server -am spring-boot:run
```

> **跨库比对必须固定服务端时区**。`DATETIME`/`TIMESTAMP` 列在 SQL 归一化阶段要按“会话时区”折算到 UTC；
> MySQL 连接的会话时区通常来自容器 `TZ`，而 PostgreSQL / Trino / Presto 的 JDBC 会话时区取自 JVM 默认时区。
> 若服务端 JVM 与数据源会话时区不一致，同一行的 `datetime` 会整体相差若干小时，表现为“几乎全表不等”的假差异。
> 因此服务端启动时请显式指定，例如 Docker：`-e TZ=Asia/Shanghai`；宿主直跑：`export TZ=Asia/Shanghai`。
> 也可在 comparison 的 `normalization` 规则里显式声明 `sessionTimeZone`（如 `+08:00`）覆盖默认行为。

默认端口 `16789`，健康检查为 `http://localhost:16789/actuator/health`，并暴露 `/actuator/health/liveness` 与 `/actuator/health/readiness` 供 Kubernetes 探针使用（readiness 含数据库健康检查，数据库不可用时摘除流量），`/actuator/info` 提供构建版本信息；进程收到 `SIGTERM` 时按 `server.shutdown=graceful` 等待在途请求（最长 30 秒）。所有响应统一带 `X-Content-Type-Options: nosniff`、`X-Frame-Options: SAMEORIGIN`、`Referrer-Policy: no-referrer` 与限制性 `Permissions-Policy`；`/v1/*` 响应额外标记 `Cache-Control: no-store`。仓库不保存数据库口令；生产环境还需通过 `CONSILENS_ENCRYPTION_KEY` 覆盖数据源密码加密密钥。

JDK 17 冒烟：

```bash
JAVA_HOME=<temurin-17> ./mvnw -B -DskipTests package
JAVA_HOME=<temurin-17> ./mvnw -B -pl :consilens-cli -am \
  -Dtest='DuckDbCompareRuntimeTest,VerifyCommandDuckDbTest,MetricDiffServiceTest' \
  -Dsurefire.failIfNoSpecifiedTests=false test
```

## 二、模块职责

开发前先确认修改点属于哪个模块：

- CLI / 配置 / 输出：`consilens-cli`
- 比对规划 / 算法 / 分段 / 差异模型：`consilens-core`
- 连接器 / 数据集抽象：`consilens-connector`
- 文件/S3/Iceberg 数据源：`consilens-connector-file`、`consilens-connector-iceberg`
- 连接器认证 testkit：`consilens-connector-testkit`
- 嵌入式 SDK：`consilens-sdk`
- Sink 输出插件：`consilens-sink`
- Plugin 运行时：`consilens-spi`
- 基准套件：`consilens-benchmark`
- MCP 适配器：`consilens-mcp`（JDK 17）
- 发行包：`consilens-dist`

### 模块依赖规则

- `consilens-core` 依赖 `consilens-connector-api`（不依赖具体连接器插件）
- `consilens-connector-base` 依赖 `consilens-connector-api`
- 连接器插件模块不得依赖 `consilens-core`
- `consilens-spi` 是通用插件基础设施，不属于 connector 语义

## 三、代码风格

项目默认约束：

- Java 11
- 四空格缩进
- 类名 `UpperCamelCase`
- 方法和字段 `lowerCamelCase`
- 常量 `SCREAMING_SNAKE_CASE`
- 引入类时使用 `import`，不要写全限定名

## 四、配置开发注意事项

配置入口是：

- [CliConfiguration.java](../consilens-cli/src/main/java/com/consilens/cli/model/CliConfiguration.java)

配置模型使用 connector/dataset 结构：

- `source/target`：各含 `type`、`name`、`connection`（连接参数）、`resource`（数据集标识）
- `comparison`：`keys`、`fields`、`filters`（原 `where`）
- `strategy`、`concurrency`、`normalization`、`result`

变更配置字段时，通常需要同时检查：

- `CliConfiguration`
- `ConfigurationManager`
- `ConfigNormalizer`
- `ConnectorConfigMapper`
- `DiffService`
- `README` 与 `docs`

建议：

- 新配置必须有默认值或兼容旧行为
- 文档要同步更新
- 示例配置要与当前实现一致

## 五、核心算法开发

### `checksum` 路径

主要类：

- [ChecksumDiffer.java](../consilens-core/src/main/java/com/consilens/core/algorithm/ChecksumDiffer.java)
- [TableSegmenter.java](../consilens-core/src/main/java/com/consilens/core/segment/TableSegmenter.java)
- [TableSegment.java](../consilens-core/src/main/java/com/consilens/core/segment/TableSegment.java)

修改这条链路时，重点关注：

- 分段边界是否有缺口或重叠
- checksum 相等时是否正确跳过
- 小段是否能及时收敛到本地比较
- `strategy.localCompare.mode` 是否按配置切到 `row-hash` 或 `full`
- `infoTree` 是否同步记录了新决策

### `join` 路径

主要类：

- [JoinDiffer.java](../consilens-core/src/main/java/com/consilens/core/algorithm/JoinDiffer.java)

修改重点：

- JOIN SQL 的正确性
- 同库校验逻辑
- 差异行的主键提取与 changed columns 输出

### 比对规划器

- [DefaultComparePlanner.java](../consilens-core/src/main/java/com/consilens/core/compare/DefaultComparePlanner.java)

规划器只基于 `CapabilitySet` 选择执行计划，不检查连接器类型。修改时确保不引入类型判断逻辑。

## 六、如何新增执行计划

当需要新增比对策略（如 `streaming` 或自定义策略）时：

### 1. 定义 PlanExecutor

实现 `PlanExecutor` 接口，放在 `consilens-core` 的 `compare/executor/` 包下：

```java
public class MyPlanExecutor implements PlanExecutor<MyPlan> {

    @Override
    public boolean supports(ComparePlan plan) {
        return plan instanceof MyPlan;
    }

    @Override
    public DiffResult execute(MyPlan plan, CompareRequest request,
                              CompareSegment source, CompareSegment target) throws Exception {
        // 使用 source/target 的 DatasetHandle/RecordScanner 执行
    }
}
```

### 2. 注册到 DefaultComparePlanner

在 `DefaultComparePlanner` 中选择新计划时，基于 `DatasetHandle` 的 `CapabilitySet` 增加分支，并通过 `CompareRequest.strategyPreference` 允许显式指定：

```java
if (source.supports(ConnectorCapability.STREAM_SCAN)
        && target.supports(ConnectorCapability.STREAM_SCAN)) {
    return new MyPlan(...);
}
```

**注意：不要在规划器中检查连接器类型（如 instanceof）**，只允许通过 `CapabilitySet` 来决策。

### 3. 在 CapabilitySet 中声明能力

若需要新的能力，在 `ConnectorCapability` 枚举中新增条目，并在对应 `DatasetHandle` 的元数据中声明。

## 七、如何新增 Sink 插件

### 1. 新建模块

建议在：

- `consilens-sink/consilens-sink-plugins/`

下新增独立模块，命名规则：`consilens-sink-<format>` 或 `consilens-sink-<format>-<type>`。

### 2. 实现 SinkProvider

实现 `SinkProvider` 接口，指定 `format` 和 `type`：

```java
public class MyCustomSinkProvider implements SinkProvider {

    @Override
    public String getFormat() {
        return "custom";
    }

    @Override
    public String getType() {
        return "diff-record";
    }

    @Override
    public Sink create() {
        return new MyCustomSink();
    }
}
```

### 3. 实现 Sink

实现 `Sink` 接口，按需覆盖所需回调：

```java
public class MyCustomSink implements Sink {

    @Override
    public void open(SinkConfig config, DiffContext context) throws Exception {
        // 解析 properties，初始化资源
        MyConfig cfg = new ObjectMapper().readValue(config.getProperties(), MyConfig.class);
    }

    @Override
    public void onDiffRecords(List<DiffRow> rows, DiffContext context) throws Exception {
        // 处理差异明细
    }

    @Override
    public void close() throws Exception {
        // 释放资源
    }
}
```

### 4. 注册 SPI

在资源目录新增：

`META-INF/services/com.consilens.sink.api.SinkProvider`

内容：

```text
com.example.MyCustomSinkProvider
```

### 5. 纳入打包

确保：

- 父 POM 引用了模块
- `consilens-sink-all` 引入了该依赖（如需内置）或单独作为插件放入 `plugins/` 目录

## 八、如何新增连接器

### 新增 JDBC 数据库连接器

#### 1. 新建模块

建议在：

- `consilens-connector/consilens-connector-plugins/`

下新增独立模块。

#### 2. 实现方言

建议继承：

- [AbstractDatabaseDialect.java](../consilens-connector/consilens-connector-plugins/consilens-connector-base/src/main/java/com/consilens/conncetor/base/AbstractDatabaseDialect.java)

至少补齐：

- `getDatabaseType()`
- `CapabilityProvider`
- `SqlQueryGenerator`
- `MetadataQueryGenerator`
- `DataTypeHandler`

#### 3. 注册 SPI

在资源目录新增：

`META-INF/services/com.consilens.connector.api.DatabaseDialectProvider`

内容：

```text
com.example.YourDatabaseDialectProvider
```

同时在 API 模块实现对应的 `DatabaseDialectProvider`。

#### 4. 纳入打包

确保：

- 父 POM 引用了模块
- `consilens-dist` 打包时能把连接器带进 `plugins/`

### 新增非 JDBC 数据源连接器

对于 Elasticsearch、MongoDB、HDFS 等非 JDBC 数据源：

1. 实现 `ConnectorProvider`，在 `createDatasetHandle()` 中返回自定义 `DatasetHandle`
2. `DatasetHandle` 通过 `getCapabilities()` 声明能力（如 `SERVER_SIDE_HASH`）
3. 实现 `DatasetHandle.getSupport(Class<T>)` 提供必要的执行支持接口
4. 注册 SPI 并纳入打包

核心规划器 `DefaultComparePlanner` 只基于 `CapabilitySet` 选择计划，不区分数据源类型，因此新连接器无需修改核心代码。

## 九、测试建议

### 单元测试

优先覆盖：

- 边界分段
- checksum 决策分支
- 能力集合与规划器选择
- 差异类型生成
- 输出格式转换

已有测试位置：

- [consilens-core/src/test/java](../consilens-core/src/test/java)
- [consilens-cli/src/test/java](../consilens-cli/src/test/java)

### 集成测试

适合覆盖：

- 不同数据库方言 SQL
- 类型标准化差异
- row-hash 本地比较在真实库上的行为

## 十、文档维护规则

凡是以下内容变化，都应同步更新文档：

- 配置字段
- 支持的输出格式
- 支持的连接器列表
- 算法阈值语义
- 打包产物结构

最常见错误是：

- 代码已经改成新配置模型，README 还保留旧 YAML 结构

## 十一、调试建议

### 看执行树

优先检查 `infoTree`：

- 哪一层开始出现差异
- 是继续分段还是转本地比较
- 哪些段被 checksum 直接跳过

### 看日志

默认日志配置在：

- [log4j2.xml](../consilens-core/src/main/resources/log4j2.xml)

启动脚本会把日志写到：

- `logs/`

### 看输出结果

优先确认：

- 主键提取是否正确
- 列名顺序是否一致
- 标准化配置是否影响值比较

## 十二、提交流程建议

建议遵循：

1. 先改代码
2. 再补测试
3. 最后更新文档
4. 本地至少执行一次 `mvn test` 或最小范围模块测试

提交信息建议使用 Conventional Commits：

- `feat:`
- `fix:`
- `refactor:`
- `docs:`

## 十三、SDK、CLI 与扩展验证

### SDK

- 入口：`consilens-sdk` 的 `ConsilensEngine`，默认实现 `DefaultConsilensEngine` 包装 `DefaultCompareRuntime`。
- 每次 `execute` 后附加 `columnStats`、`schemaCompatibility`、`fingerprint`、`evidence`。
- 预算、listener、进度回调通过 `RunOptions` 传入。
- 修改 SDK 公开表面后运行：

```bash
./mvnw -B -pl :consilens-sdk -am -Dtest=SdkApiCompatibilityTest test
```

### CLI 命令

| 命令 | 作用 |
| --- | --- |
| `diff` | 数据比对；`--engine java\|duckdb` |
| `verify` | CI 门禁 + 报告；支持 `--engine duckdb` |
| `metrics` | 指标聚合/分组；`--engine java\|duckdb` |
| `contract diff` / `contract init` | ODCS/dbt 契约比较与配置骨架 |
| `connector certify` | 连接器认证 |

### 连接器认证

第三方连接器在测试中依赖 `consilens-connector-testkit`：

```java
CertificationReport report = ConnectorCertification.verify(provider, config, keySpec, 100);
assertTrue(report.isPassed(), report.failures().toString());
```

修改 SPI 后运行：

```bash
./mvnw -B -pl :consilens-connector-testkit -am -Dtest=SpiApiCompatibilityTest test
```

### DuckDB 引擎

- `DuckDbFileSql` 负责文件表表达式；`DuckDbCompareRuntime` 负责行级 diff；`DuckDbMetrics` 负责聚合。
- 新增文件格式时同步：`FileFormat`、`FilePaths`、`DuckDbFileSql`、文件扫描器与测试。
- DuckDB 只用于本地文件；S3 走默认 runtime。
- 修改后至少运行 `DuckDbCompareRuntimeTest`、`MetricDiffServiceTest`、`VerifyCommandDuckDbTest`。
