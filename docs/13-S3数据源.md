# S3 数据源

`file` 连接器支持 `s3://` 与 `s3a://` 对象。实现方式是把对象下载到本地临时目录，再复用 CSV/JSONL/Parquet 扫描器与 streaming plan，因此比对语义与本地文件完全一致。

## 一、配置

```yaml
source:
  type: file
  name: source-s3
  resource:
    type: file
    path: s3://my-bucket/export/2026-10/*.parquet
    format: parquet
    options:
      s3Region: eu-central-1
      # MinIO / 本地兼容存储：
      # s3Endpoint: http://127.0.0.1:9000
      # s3PathStyle: true
      # s3AccessKey: minio
      # s3SecretKey: minio123
```

| 选项 | 说明 |
| --- | --- |
| `s3Region` | 区域；缺省读 `AWS_REGION`，再缺省 `us-east-1` |
| `s3Endpoint` | 自定义 endpoint（MinIO、LocalStack 等） |
| `s3PathStyle` | 使用 path-style 访问；MinIO 通常需要 |
| `s3AccessKey` / `s3SecretKey` | 静态凭据；必须成对配置 |
| `s3MaxObjectBytes` | 单个对象上限，默认 2 GiB；超限时报错并删除半成品文件 |
| `s3MaxTotalBytes` | 本次下载总量上限，默认 8 GiB；用于限制"前缀下对象很多"时的磁盘占用 |
| 未配置凭据 | 使用 AWS 默认凭据链（环境变量、profile、IAM role 等） |

选项既可以平铺在 `resource` 下，也可以收在 `options` 块里，两种写法等价
（见 [配置详解](./02-配置详解.md) 的「资源选项」一节）。

下载始终是"边读边写本地临时文件"，不把对象读进堆；两个 `s3Max*` 选项限制的是**磁盘**占用：
一个异常的（或恶意的）超大对象原本可以把磁盘写满、把整个比对拖挂。超限时会删掉半成品文件再报错，
不会留下一个看起来完整的截断文件。

## 二、路径形式

| 路径 | 行为 |
| --- | --- |
| `s3://bucket/key.csv` | 下载单个对象 |
| `s3://bucket/prefix/` | 列出前缀下所有 `.csv/.jsonl/.ndjson/.parquet` 对象 |
| `s3://bucket/prefix/*.parquet` | 列出 glob 前缀，按通配符过滤 |
| `s3://bucket/**/*.csv` | `**` 跨目录匹配 |

- 前缀/glob 会忽略目录标记（以 `/` 结尾的 key）和非数据扩展名。
- 单对象不校验扩展名，由 `format` 或内容决定解析方式。
- 列出的对象数量上限为 10,000，超过会报错，需收窄前缀或 glob。
- 多文件 schema 规则与本地目录一致：文本格式取首个文件，Parquet 使用 `union_by_name=true`。

## 三、生命周期

- 打开数据集时下载对象到 `consilens-s3-*` 临时目录，文件名带序号前缀避免同名冲突。
- `DatasetHandle.close()` 递归删除临时目录；正常 CLI 流程在比对结束后关闭。
- 进程异常退出时临时目录可能残留，由操作系统临时目录清理策略回收。
- 不支持 range read、S3 Select 或 predicate pushdown；每次比对都会完整下载匹配对象。

## 四、依赖与安全

- 发行包（`consilens-connector-all`）已内置 `software.amazon.awssdk:s3`，并排除了 Netty 异步客户端，使用同步 Apache client。
- 自行裁剪依赖时需保留 `software.amazon.awssdk:s3`；缺失时会得到明确的 “S3 support requires ...” 错误。
- 凭据不会写入日志、指纹或结果 artifact；建议使用 IAM role 或环境变量，避免在 YAML 中硬编码。
- 当前不暴露 SSE-KMS、requester-pays、S3 Object Lambda 等高级选项。

## 五、示例

```bash
consilens-cli.sh diff -c examples/files/s3-to-csv.yaml
```

示例默认指向本地 MinIO（`http://127.0.0.1:9000`、`s3PathStyle: true`）；示例文件需自行准备
bucket 与对象，仓库不包含真实凭据。

## 六、冒烟验证

`scripts/s3-smoke.sh` 对真实 S3 兼容存储执行一组端到端检查，覆盖：

| 检查 | 内容 |
| --- | --- |
| 单对象 | `s3://bucket/key.csv` 与本地文件比对 |
| 前缀 | 目录多对象合并，目录标记对象与非数据扩展名被忽略 |
| glob | `*.csv`（单层）与 `**/*.csv`（跨目录） |
| JSONL / Parquet | 对象分别与本地 JSONL、本地 CSV 比对（跨格式） |
| 凭据链 | 不写静态凭据，走 `AWS_ACCESS_KEY_ID` 等默认链 |
| 错误路径 | 前缀无对象时明确报错，不静默产出 0 差异 |
| 生命周期 | 比对结束后 `consilens-s3-*` 临时目录已删除 |

```bash
# 需要 MinIO（或其他 S3 兼容服务）与 mc 客户端
S3_ENDPOINT=http://127.0.0.1:9000 \
S3_ACCESS_KEY=minioadmin S3_SECRET_KEY=minioadmin \
MC_BIN=/path/to/mc \
scripts/s3-smoke.sh
```

脚本会在 `S3_PREFIX`（默认 `s3-smoke`）下准备对象，结束后清理；`S3_SMOKE_KEEP=1` 可保留现场。
2026-10-30 本机以 MinIO `RELEASE.2025-07-23` 实测 10 项检查全部通过。
