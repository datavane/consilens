# 兼容性策略

Consilens 的目标是让平台、第三方连接器和 CI 集成可以在 1.x 周期内稳定升级。兼容性分为 SDK、连接器 SPI、配置 schema、结果/artifact 与 CLI 退出码五层。

## 一、版本规则

- **主版本**：删除/重命名公开方法、改变既有语义、改变退出码、移除配置字段、要求新必填字段。
- **次版本**：新增方法/字段/枚举值、新增可选配置、新增连接器类型；旧调用方不需要修改。
- **补丁版本**：bugfix、性能、文档，不改变契约。

`EngineInfo.API_VERSION` 当前为 `1.0`，只在主版本变更时提升。`EngineInfo.version` 是引擎发行版本，两者独立。

## 二、稳定表面

| 表面 | 稳定性 | 守卫 |
| --- | --- | --- |
| `ConsilensEngine` / `RunOptions` / `RunListener` / `EngineInfo` | 稳定 | `SdkApiCompatibilityTest` |
| `VerifyPolicy` / `VerifyResult` / `Verdict` / 退出码 | 稳定 | `SdkApiCompatibilityTest`、`VerifyCommandTest` |
| `ConnectorProvider` / `ConnectorAdapter` / `DatasetHandle` / `RecordScanner` / `CanonicalRecord` | 稳定 | `SpiApiCompatibilityTest` |
| `CompareRequest` / `CompareExecutionOptions` / `CompareSegment` | 稳定（只增字段） | `SpiApiCompatibilityTest` || CLI YAML 配置 | 稳定（只增可选字段） | `LegacyConfigurationCompatibilityTest`、`ExampleConfigurationCompatibilityTest` |
| `DiffResult` 字段 | 稳定（只增字段） | `SdkApiCompatibilityTest`、结果/artifact 测试 |
| 结果 artifact metadata | 稳定（只增键） | `DiffReportServiceImplTest`、`RunTaskHandlerTest` |
| CLI 退出码 | 稳定 | `SdkApiCompatibilityTest`、文档 |

## 三、SDK

- 新增能力优先放在 `RunOptions` 或新接口，不污染 `CompareRequest` 的既有语义。
- `DiffResult` 只做增量字段扩展；既有 getter 的返回类型与语义不变。
- 监听器回调新增时提供 `default` 方法，避免破坏已有实现。
- 删除/改签名必须提升 `EngineInfo.API_VERSION` 并在 release notes 标注迁移方式。

## 四、连接器 SPI

- `ConnectorProvider.getType()` 返回的类型字符串是稳定标识，不随实现重构改变。
- `DatasetHandle` 的可选能力通过 `Optional` + `getSupport` 表达；新增能力用新接口，不改既有方法签名。
- `RecordScanner.scan(CompareSegment)` 的规范值形态与 `ValueNormalizer` 口径保持一致。
- 第三方连接器应通过 `consilens-connector-testkit` 的 `ConnectorCertification` 自检，并在 CI 中固定依赖的 Consilens 次版本。

## 五、配置与结果

- 旧配置不需要新增字段即可加载；新字段都有默认值或 `null` 语义。
- 配置同时支持 YAML/JSON；`${env.NAME:default}` 占位符在加载时解析。
- 未知配置字段默认拒绝，用于捕获拼写错误；新增字段必须保持可选，避免破坏旧配置。
- 旧 artifact/结果 JSON 缺少新字段时，读取方必须按“缺失=未提供”处理；server 的 `DiffReportServiceImpl` 已按此实现。
- 新 artifact 在 metadata 中写入 `resultSchemaVersion`（当前 `DiffResult.RESULT_SCHEMA_VERSION = 1`）；旧 artifact 没有该字段，报告返回 `null`，不得据此拒绝读取。
- 结果 schema 版本只在字段语义变化或新增必填字段时提升；新增可选字段不提升。
- 下游解析 artifact 时应忽略未知字段，避免新版本新增字段导致反序列化失败。
- 不兼容的配置语义变化（例如把某个默认值改成相反含义）按主版本处理。

## 六、兼容性测试

```bash
# SDK 表面
./mvnw -pl :consilens-sdk -am test -Dtest=SdkApiCompatibilityTest

# 连接器 SPI
./mvnw -pl :consilens-connector-testkit -am test -Dtest=SpiApiCompatibilityTest

# 旧配置
./mvnw -pl :consilens-cli -am test -Dtest=LegacyConfigurationCompatibilityTest

# 全部示例配置
./mvnw -pl :consilens-cli -am test -Dtest=ExampleConfigurationCompatibilityTest
```

这些测试在正常构建中运行；删除公开方法或改变签名会让构建直接失败。

## 七、弃用流程

1. 标记 `@Deprecated` 并在 Javadoc 说明替代方案与预计移除版本。
2. 至少保留一个次版本，期间新旧路径并存。
3. 在主版本移除，并在 release notes 中列出迁移步骤。
4. 配置字段弃用先转为“读取但警告”，再在主版本移除。
