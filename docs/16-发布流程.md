# 发布流程

本文件描述从 `main` 生成 Consilens 发行包与发布工件（sources/Javadoc/SBOM）的步骤。Maven Central 的 GPG 签名与 deploy 仍需发布凭据，当前未自动化。

## 一、前置检查

```bash
python3 scripts/release/check-pom-versions.py
./mvnw -B test
```

`check-pom-versions.py` 校验所有模块的 parent/自身版本与根 POM 一致。版本不一致时本地可能因 `~/.m2` 残留旧 parent 而“构建成功”，干净环境则会报 `parent.relativePath points at wrong local POM`。

`scripts/release/release-check.sh` 还会运行 server 打包/冒烟、外部数据库测试等门禁；完整发布以该脚本为准。无 Docker 环境可加 `--skip-docker`，其余门禁照常执行。`root-tests` 使用 `clean test`，避免陈旧 `target/`（尤其是 shaded CLI jar）污染测试类路径。门禁日志与 smoke 产物写入 `.release-checks/<run-id>/`（已被 `.gitignore` 忽略），不会因 `clean` 丢失。

发布 server jar 前必须先构建前端，否则 `static/` 为空：

```bash
./mvnw -B -Prelease -pl consilens-ui package
./mvnw -B -pl consilens-server -am -DskipTests package
```

该步骤已包含在 `release-check.sh` 的 `ui-package` gate 中。UI release profile 依次执行 `npm ci` → `npm test` → `vite build`，前端单测失败会阻断发布。server 在复制 UI 资源前会清理源码与 `target/classes` 下的旧 `static/`，避免历史哈希文件进入 jar；`server-smoke` 会校验 jar 内静态文件数与 `consilens-ui/dist` 完全一致。

## 二、发行包

```bash
./mvnw -B -Prelease -pl consilens-dist -am package -DskipTests
```

产物：

```text
consilens-dist/target/consilens-<version>.tar.gz
```

包内包含：

- `bin/`、`libs/`、`plugins/`、`conf/`、`examples/`、`mcp-skills/`、`docs/`
- `VERSION`、`LICENSE`、`README.md`、`SECURITY.md`、`SUPPORT.md`
- `sbom/bom.json`、`sbom/bom.xml`（CycloneDX 1.5）

GitHub Release 附件包括：

- `consilens-<version>.tar.gz`
- `bom.json`、`bom.xml`
- `SHA256SUMS`（发行包、SBOM、server/MCP 主 jar；按 Release 资产文件名生成，
  下载后可 `sha256sum -c SHA256SUMS` 校验）
- `consilens-server-*.jar`、`consilens-mcp-*.jar`

`SHA256SUMS` 由 release workflow 在发布前生成；任一附件缺失会让工作流失败。

## 三、sources 与 Javadoc

```bash
./mvnw -B -Prelease,javadoc -pl consilens-dist -am install -DskipTests
```

- `release` profile 为每个模块附加 `-sources.jar`。
- `javadoc` profile 为每个模块附加 `-javadoc.jar`。
- 必须使用 `install`：Javadoc 插件会 fork Maven 解析 module 依赖，`package` 阶段 reactor 依赖尚未安装会失败。
- 聚合模块可能输出 `Error fetching link ... Ignored it.`，不影响构建。

## 四、SBOM

`cyclonedx-maven-plugin` 在 `release` profile 的 `package` 阶段生成：

- 每个模块：`target/bom.json` / `target/bom.xml`
- `consilens-dist/target/bom.json`：发行包依赖的聚合 SBOM

发行包内副本位于 `sbom/`。发布前建议：

```bash
python3 -m json.tool consilens-dist/target/bom.json > /dev/null
```

并审查新增/升级依赖的许可证与已知漏洞。

离线策略检查：

```bash
python3 scripts/release/check-sbom.py consilens-dist/target/bom.json
# 警告也视为失败：
python3 scripts/release/check-sbom.py consilens-dist/target/bom.json --strict
```

检查项：

- `bomFormat`、`specVersion`（1.4/1.5/1.6）、组件非空。
- 每个组件必须有 `type`/`name`/`version`；禁止 `latest`/`unknown` 版本。
- 缺少 `purl`、缺少许可证、重复 `purl` → warning。
- `AGPL-*`、`SSPL-1.0` → error；`GPL-*`、`LGPL-*`、`EPL-*`、`MPL-2.0` → warning 待人工复核。
- 默认 warning 不阻断；`--strict` 时阻断。

`release-check.sh` 的 `sbom-policy` 门禁会自动运行该脚本。

## 五、发布门禁

`scripts/release/release-check.sh` 的 `release-package` 门禁使用：

```bash
./mvnw -B -Prelease,javadoc -pl consilens-dist -am install -DskipTests
```

## 六、Maven Central（opt-in）

`publish` profile 提供 GPG 签名与 Sonatype Central Publishing：

```bash
./mvnw -B -Prelease,javadoc,publish deploy -DskipTests
```

本地可用 `file://` 仓库完整演练 deploy（不接触 Sonatype）：

```bash
rm -rf /tmp/consilens-repo
./mvnw -B -Prelease,javadoc -DskipTests \
  -Dconsilens.deploy.skip.apps=true \
  -DaltDeploymentRepository='local::default::file:///tmp/consilens-repo' \
  deploy
```

检查 `com/consilens/consilens-sdk/...` 下应同时存在：

```text
*.jar
*-sources.jar
*-javadoc.jar
*-cyclonedx.json / *.xml
*.pom
```

`publish` 与本地演练建议设置 `consilens.deploy.skip.apps=true`：`consilens-dist`、`consilens-server`、`consilens-mcp` 作为应用包通过 GitHub Release 分发，不上传 Maven Central。该属性默认 `false`，所以普通 `-Prelease` 打包仍会生成 SBOM 与发行包。

前置条件：

- 已生成并上传 GPG 公钥；本地私钥可用。
- `~/.m2/settings.xml` 中配置 server id `central`（Sonatype 用户 token）：
  ```xml
  <server>
    <id>central</id>
    <username>TOKEN_USER</username>
    <password>TOKEN_PASSWORD</password>
  </server>
  ```
- GPG 口令通过 `MAVEN_GPG_PASSPHRASE` 或 gpg-agent 提供。
- `central-publishing-maven-plugin` 默认 `autoPublish=true`；需要人工检查 staging 时改为 `false`。

说明：

- `deploy` 会跑完整生命周期到 `verify`，因此会触发 GPG 签名；`-Dgpg.skip=true` 可用于本地干跑（不发布）。
- `release`/`javadoc`/`publish` 三个 profile 必须同时启用；`publish` 只负责签名与上传，不生成 sources/javadoc/SBOM。
- 首次发布前建议在 staging 上核对：主 jar、sources、javadoc、pom、CycloneDX JSON/XML 是否齐全。

## 七、尚未自动化

- 发布说明由 GitHub Release 自动生成（`generate_release_notes`）。
- 制品 GPG 签名发布到 GitHub Release（当前只有 SHA256SUMS）。
- 发布失败后的自动回滚/重试。
