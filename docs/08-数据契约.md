# 数据契约（ODCS / dbt）

`contract diff` 比较两份数据契约的 schema，用于在数据比对之外检查“表结构是否按契约演进”。它支持 ODCS v3 与 dbt `schema.yml`，是纯离线命令，不连接数据库。

## 一、命令

```bash
consilens-cli.sh contract diff \
  --source contracts/users-source.odcs.yaml \
  --target contracts/users-target.yml \
  --target-model users \
  --format markdown
```

| 选项 | 说明 |
| --- | --- |
| `-s, --source` | 源契约文件（YAML 或 JSON） |
| `-t, --target` | 目标契约文件 |
| `--source-model` | dbt 源文件包含多个 model/source table 时指定名称 |
| `--target-model` | dbt 目标文件包含多个 model/source table 时指定名称 |
| `--format` | `markdown`（默认）或 `json` |
| `-o, --output` | 写入文件；省略时输出到 stdout |
| `--no-fail` | 有差异也返回 0，适合只出报告的场景 |

退出码：`0` 契约一致（或 `--no-fail`）；`1` 存在差异；`2` 解析/写文件失败。

文件格式自动识别：包含 `models` 或 `sources` 视为 dbt，否则按 ODCS 解析。dbt 文件只有一个 model/source table 时可省略 `--*-model`。

## 二、生成比对配置骨架

```bash
consilens-cli.sh contract init \
  --source contracts/users-source.odcs.yaml \
  --target contracts/users-target.odcs.yaml \
  --source-type mysql --target-type postgresql \
  --output compare.yaml
```

生成内容只包含契约能确定的部分：

```yaml
source:
  type: mysql
  name: users
  resource:
    type: table
    name: users
target:
  type: postgresql
  name: users
  resource:
    type: table
    name: users
comparison:
  keys:
    source: [id]
    target: [id]
  fields:
    source: [email, amount]
    target: [email, amount]
result:
  sinks:
    - format: console
      type: result
```

规则：

- 键默认取源契约的 `primaryKey`；没有主键时必须用 `--keys id[,..]` 指定，且键必须同时存在于两侧。
- 比较字段取两侧列名的交集（排除键），保持源契约顺序；源独有/目标独有的列不会写入。
- 连接 URL、账号、密码、schema 等不会被猜测，需要用户补齐后再执行 `validate`。
- 退出码：`0` 生成成功；`2` 读取、键选择或写文件失败。

## 三、支持的 ODCS 子集

```yaml
apiVersion: v3.0.2
kind: DataContract
id: users-contract
name: users
schema:
  - name: users
    primaryKey: [id]
    properties:
      - name: id
        logicalType: integer
        physicalType: bigint
        required: true
      - name: email
        logicalType: string
        physicalType: varchar(255)
        required: true
        unique: true
      - name: amount
        logicalType: number
        physicalType: decimal(18,2)
```

- `schema` 或 `dataset`，对象或数组均可；列集合来自 `properties` 或 `fields`。
- 列类型优先使用 `physicalType`，缺失时回落到 `logicalType`；比较时忽略大小写与首尾空格。
- `required` 缺失时可由 `nullable: false` 推导。
- 主键：列上的 `primaryKey: true`、`keyType: primary`，或 schema 级 `primaryKey: [id]`。
- 其他支持字段：`unique`。

## 四、dbt `schema.yml`

```yaml
version: 2
models:
  - name: users
    columns:
      - name: id
        data_type: bigint
        constraints:
          - type: not_null
          - type: primary_key
      - name: email
        data_type: varchar(255)
        tests:
          - unique
          - not_null
sources:
  - name: raw
    tables:
      - name: users
        columns:
          - name: id
            data_type: bigint
```

| dbt 字段 | 映射 |
| --- | --- |
| `data_type` / `dataType` | 列类型（physicalType） |
| `constraints[].type` | `not_null` → required；`unique` → unique；`primary_key` → primaryKey |
| `tests[]`（字符串或对象键） | 同上；`not_null`、`unique`、`primary_key` |
| `meta.required` / `meta.unique` / `meta.primary_key` | 布尔标记 |
| `required` | 列级显式覆盖 |

`models[]` 与 `sources[].tables[]` 都会被收集；多个候选时必须用 `--source-model` / `--target-model` 指定。

## 五、差异类型

| 类型 | 含义 |
| --- | --- |
| `COLUMN_ADDED` | 目标契约新增列 |
| `COLUMN_REMOVED` | 目标契约删除列 |
| `TYPE_CHANGED` | 物理/逻辑类型变化 |
| `REQUIRED_CHANGED` | 必填性变化 |
| `UNIQUE_CHANGED` | 唯一性变化 |
| `PRIMARY_KEY_CHANGED` | 主键标记变化 |

Markdown 报告按列列出 source/target 值；JSON 报告包含 `identical`、`changes[]`、`sourceName`、`targetName`。

## 六、限制

- 只比较 schema，不校验 `servers`、连接信息、质量规则（quality）与 SLA。
- 列名大小写敏感；类型比较不展开 `varchar(255)` 与 `varchar(100)` 的兼容性，按字符串是否相等判断。
- `required`/`unique`/`primaryKey` 的“未声明”与 `false` 视为相同，避免 ODCS 省略字段与 dbt 显式约束产生噪声。
- 不生成比对配置；契约到 `source/target/keys/fields` 的映射需要用户显式确认，避免猜测连接与服务信息。
