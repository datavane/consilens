# 指标比对（metric diff）

`metrics` 子命令在现有比对配置的两侧分别聚合指标，再比较结果。它复用连接器 `RecordScanner`，因此文件源和 JDBC 源都能使用，不需要为每个数据库写 SQL。

## 一、命令

```bash
consilens-cli.sh metrics \
  --config compare.yaml \
  --metric count \
  --metric nulls:amount \
  --metric sum:amount \
  --metric avg:amount \
  --max-relative-delta 0.5 \
  --engine java \
  --format markdown
```

| 选项 | 说明 |
| --- | --- |
| `-c, --config` | 现有比对配置文件 |
| `--metric` | 可重复或逗号分隔的指标表达式 |
| `--engine` | `java`（默认，走 RecordScanner）或 `duckdb`（本地文件 SQL 聚合） |
| `--group-by` | 逗号分隔的维度列；Java/DuckDB 引擎均支持 |
| `--max-absolute-delta` | 绝对差值上限，默认 0 |
| `--max-relative-delta` | 相对差值上限（百分比），默认 0 |
| `--format` | `markdown`（默认）或 `json` |
| `-o, --output` | 写入文件；省略时输出到 stdout |

未提供 `--metric` 时默认只算 `count`。

## 二、指标表达式

| 表达式 | 含义 |
| --- | --- |
| `count` | 行数 |
| `count:col` | 非 NULL 行数 |
| `nulls:col` | NULL 行数 |
| `sum:col` | 数值列求和 |
| `min:col` / `max:col` | 数值列最小/最大值 |
| `avg:col` | 数值列平均值（保留 6 位，输出去掉尾零） |

数值列支持 `Number` 与可解析为数字的字符串；遇到其他类型直接报错，避免静默产生错误汇总值。

## 三、容差

对每个指标计算：

```text
delta      = target - source
relative % = |delta| / max(|source|, |target|) * 100
```

判定为通过的条件（OR）：

```text
|delta| <= maxAbsoluteDelta  OR  relative % <= maxRelativeDelta
```

因此两个容差都为 0 时是精确比较；只设置相对容差时适合金额/计数这类量级差异；只设置绝对容差时适合小数抖动。

## 四、DuckDB 引擎

`--engine duckdb` 把聚合下推给本地 DuckDB，适合大文件：

```bash
consilens-cli.sh metrics -c compare.yaml --engine duckdb \
  --metric count --metric nulls:amount --metric sum:amount
```

- 仅支持本地文件源（CSV/JSONL/JSON/Parquet）；S3 会明确报错，请使用默认 `java` 引擎。
- 目录/glob 必须显式配置 `format`，否则无法确定文件类型。
- CSV 支持 `delimiter`、`hasHeader`、`nullValue`、`skipRows`；不支持自定义 charset。
- Parquet 使用 `read_parquet(..., union_by_name=true)`；JSONL 使用 `read_json_auto`。
- 仍不支持 `comparison.mappings` / `comparison.filters`。
- Java 与 DuckDB 引擎的指标口径应一致；如有差异，以 Java 引擎为准并提 issue。

### 分组下钻

```bash
consilens-cli.sh metrics -c compare.yaml --engine duckdb \
  --group-by category,region \
  --metric count --metric sum:amount
```

- 维度列可以不参与 `comparison.fields`，直接读取原始列。
- 两侧按维度值对齐；某侧缺失的分组会显示该侧值为空并判 FAIL。
- 分组键对数值做规范化（如 `1.0` 与 `1` 视为同组）。
- Markdown 报告在有分组时自动增加 `Group` 列；JSON 每条结果带 `group` 字段。
- Java 引擎通过 RecordScanner 流式聚合，适用于 JDBC/Iceberg/S3；DuckDB 引擎把分组下推给本地文件 SQL，适合大文件。
- Java 引擎的分组状态保存在内存中，分组基数极大时需关注堆占用；DuckDB 引擎由 DuckDB 管理。

## 五、输出

Markdown：

```text
# Metric diff

- passed: false

| Metric | Source | Target | Delta | Relative % | Status |
| --- | --- | --- | --- | --- | --- |
| count | 3 | 3 | 0 | 0 | PASS |
| nulls:amount | 1 | 0 | -1 | 100 | FAIL |
| sum:amount | 30 | 61 | 31 | 50.8197 | FAIL |
```

JSON 包含 `passed` 与 `metrics[]`，字段为 `metric`、`sourceValue`、`targetValue`、`delta`、`relativePercent`、`passed`。缺失值用 `null` 表示，Markdown 中显示为 `-`。

退出码：`0` 全部通过；`1` 至少一个指标超差；`2` 配置/执行错误。

## 六、限制

- 默认 Java 引擎按行扫描后聚合，没有 SQL 下推；大表可改用 `--engine duckdb`（仅本地文件）。- 不支持 `comparison.mappings`；指标列必须是物理列名。需要映射时请使用 SQL 资源。
- 文件源不支持 `comparison.filters`，会直接报错，避免过滤被静默忽略。
- 指标基于原始值，不应用 `normalization` 规则；浮点容差请用命令行的差值容差。
- 不强制 `readOptions.consistency=snapshot`；需要一致性快照时请使用支持快照的 JDBC 源并自行确认。
