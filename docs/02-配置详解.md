# 配置详解

Consilens 当前使用结构化的 CLI 配置模型，配置入口对应 *CliConfiguration.java*。

## 完整示例

```yaml
source:
  type: mysql
  name: source-mysql
  connection:
    url: jdbc:mysql://localhost:3306/source_db?useSSL=false&serverTimezone=UTC
    username: root
    password: secret
  resource:
    type: table
    name: public.orders

target:
  type: postgresql
  name: target-postgresql
  connection:
    url: jdbc:postgresql://localhost:5432/target_db?currentSchema=public&ssl=false&ApplicationName=consilens
    username: postgres
    password: secret
  resource:
    type: table
    name: public.orders

comparison:
  keys:
    source:
      - order_id
    target:
      - order_id
  fields:
    source:
      - order_id
      - customer_id
      - amount
      - status
      - created_at
    target:
      - order_id
      - customer_id
      - amount
      - status
      - created_at
  filters:
    source: created_at >= '2026-01-01'
    target: created_at >= '2026-01-01'

strategy:
  mode: checksum
  algorithm: xor
  bisectionFactor: 8
  bisectionThreshold: 5000
  batchSize: 1000
  localCompare:
    mode: full

result:
  sinks:
    - format: console
      type: result
    - format: json
      type: diff-record
      properties:
        path: ./results/orders_diff.json
        pretty: true
    - format: table
      type: diff-record
      properties:
        url: jdbc:mysql://localhost:3306/consilens_results
        username: writer
        password: secret
        prefix: diff_results_
        suffixTimestamp: true
        createTable: true
        batchSize: 1000

normalization:
  global:
    decimal:
      precision: 2
      rounding: true
    timestamp:
      format: yyyy-MM-dd HH:mm:ss
      timezone: UTC
```

## 一、连接器与数据集配置

### 连接器配置

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `source.type` | 否 | 连接器类型（如 `mysql`、`postgresql`），未填时从 URL 推断 |
| `source.name` | 否 | 连接器名称，用于日志和结果标识 |
| `source.connection.url` | 是 | JDBC URL |
| `source.connection.username` | 是 | 用户名 |
| `source.connection.password` | 否 | 密码 |
| `source.resource.type` | 否 | 资源类型（如 `table`），默认 `table` |
| `source.resource.name` | 是 | 数据集名称（表名），支持 `schema.table` |
| `target.*` | — | 同 `source` 结构 |

`connection` 支持额外的 key-value 属性，如连接池参数等，直接写在 `connection` 下即可。

### 资源选项（`resource.options`）

`resource` 下的非保留字段都是资源选项，交给对应连接器解析（如 `format`、`delimiter`、
`s3Endpoint`、`snapshotId`）。两种写法等价：

```yaml
# 写法 A：直接平铺在 resource 下
resource:
  type: file
  path: s3://bucket/export/*.parquet
  s3Endpoint: http://127.0.0.1:9000
  s3PathStyle: true

# 写法 B：收敛在 options 块中（docs/13、docs/15 使用该写法）
resource:
  type: file
  path: s3://bucket/export/*.parquet
  options:
    s3Endpoint: http://127.0.0.1:9000
    s3PathStyle: true
```

`resource.type` 的取值：

| 取值 | 说明 |
| --- | --- |
| `table` | 表（默认），必须配置 `name`，不能配置 `path` |
| `sql` | 可信 SELECT/WITH 查询，写在 `path` 中 |
| `file` | 本地或对象存储文件/目录/glob，`name` 或 `path` 均可 |
| 与 `source.type`/`target.type` 同名 | 连接器自有资源类型，如 `iceberg`；配置 `name` 或 `path` 即可 |

`source.type` 为 `file` 或 `iceberg` 时不需要 `connection` 块；其余类型必须提供连接信息。

### 环境变量占位符

配置文件中的字符串值支持环境变量占位符，语法为：

```
${env.VAR_NAME}
${env.VAR_NAME:默认值}
```

示例：

```yaml
source:
  connection:
    url: ${env.SOURCE_URL:jdbc:mysql://localhost:3306/db}
    username: ${env.SOURCE_USER:root}
    password: ${env.SOURCE_PASSWORD}
```

敏感字段（密码等）建议始终通过环境变量传入，避免明文写入配置文件。

### 比对列配置

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `comparison.keys.source` | 是 | 源数据集主键列列表 |
| `comparison.keys.target` | 是 | 目标数据集主键列列表 |
| `comparison.fields.source` | 否 | 源数据集参与比较字段 |
| `comparison.fields.target` | 否 | 目标数据集参与比较字段 |
| `comparison.filters.source` | 否 | 源数据集过滤条件 |
| `comparison.filters.target` | 否 | 目标数据集过滤条件 |

注意：

- 两侧主键列数量必须一致。
- `comparison.fields` 若为空，当前代码不会自动补齐全表字段，建议明确配置。
- 过滤条件会直接拼接到分段查询里，应保证两侧语义等价。

## 二、策略与算法

### `strategy`

支持值：

- `checksum`
- `join`

实际状态：

- `checksum`：已实现，支持跨数据源
- `join`：已实现，但要求两侧数据集在同一个 JDBC URL

### `algorithm`

支持值：

- `concat`
- `xor`

建议：

- 小表或验证场景：`concat`
- 大多数大表：`xor`

说明：

- `algorithm` 只决定分段阶段的摘要计算方式
- `concat` 更直观，但通常更适合小表或验证场景
- `xor` 是跨数据源大表的默认推荐值

### 终局本地比较

终局本地比较默认使用完整行比较：

```yaml
strategy:
  localCompare:
    mode: full
```

可选值：

- `full`：默认值，直接拉取当前小段完整行做本地比较
- `row-hash`：先拉主键 + 行哈希，在本地找出差异键后再回查完整行

`row-hash` 只有显式配置时才会启用：

```yaml
strategy:
  localCompare:
    mode: row-hash
```

一般建议保持默认 `full`。只有在表非常宽、最终小段仍较大且差异行比例很低时，再考虑显式启用 `row-hash`。

### 键策略

```yaml
strategy:
  # 是否要求键唯一（严格档）。默认 false：重复键按多重集语义比较；
  # true：比对前做唯一键探针，命中重复键直接失败并列出键与行数。
  validateUniqueKeys: false
  # 是否允许可空键列。默认 false：键列在元数据中可空时直接拒绝比对，
  # 避免 NULL 键行因 SQL 三值逻辑落在分段之外被静默漏报；
  # true：允许可空键，NULL 键按引擎的 IS NULL/归一化语义参与比较。
  allowNullableKeys: false
```

- `validateUniqueKeys` 与 `allowNullableKeys` 互相独立，可以组合使用。
- 如果键列在 DDL 中可空、但业务上保证没有 NULL，推荐显式设置 `allowNullableKeys: true`，而不是依赖元数据的可空标记。
- 打开 `allowNullableKeys` 时，两侧必须对 NULL 的排序/比较语义一致；跨方言比较时尤其要注意（例如 Oracle 的空串即 NULL）。
- 也可以继续用 `IS NOT NULL` 过滤排除 NULL 键，此时无需打开该开关。

### 预算（可选）

```yaml
strategy:
  # 墙钟预算（毫秒）；超限抛 BudgetExceededException
  maxDurationMs: 3600000
  # 累计扫描行数预算；在已知取数点累计（checksum 取数/回查、streaming 逐行）
  maxRowsScanned: 100000000
  # 累计取回字节预算；在已知取数点累计（流式路径不含字节计数）
  maxBytesFetched: 1073741824
```

- 三个字段都可选；未配置表示不限。
- 超限抛出 `BudgetExceededException`：本地执行任务标记为 `BUDGET_EXCEEDED` 失败（不可重试），不会静默把部分结果当成"通过"。
- 覆盖范围：checksum 路径在行哈希/全量取数/按键回查处累计；streaming 路径逐行累计（不含字节）；join 路径按段级差异输出行数累计。
- ⚠️ `pushdown-checksum`（同库 JDBC 的默认计划）纯走 SQL 哈希时**行不在本地过**，`maxRowsScanned` 不会累计；
  只有"哈希不一致、回退到本地比对"的分段才计数。仓库已在 CLI 里对这种情况打印 WARN，
  需要硬上限请用 `maxDurationMs` 或改用 `join` / `java` 引擎。
- `maxDifferences` 是差异结果的上限，与这三个"扫描/取数"预算互相独立。

## 三、checksum 递归参数

### `bisectionFactor`

首轮分段使用的目标分段数。

示例：

- `bisectionFactor: 8` 表示初始更偏向按 8 段切分

### `bisectionThreshold`

本地比较阈值，也是递归切换策略的核心参数。

当前实现行为：

1. 全表或大段先按 `bisectionFactor` 做首轮分段
2. 若子段 `maxRows > bisectionThreshold * bisectionFactor`，仍允许继续多路分段
3. 若子段 `maxRows <= bisectionThreshold * bisectionFactor`，切换为真正二分
4. 若当前段 `totalRows < bisectionThreshold`，直接本地比对

所以：

- “切到二分”的隐含阈值 = `bisectionThreshold * bisectionFactor`
- “切到本地拉数”的阈值 = `bisectionThreshold`

### `batchSize`

当前主要用于默认计算 `bisectionThreshold`：

- 如果未显式配置 `bisectionThreshold`
- 则默认取 `batchSize * 10`

## 四、并发配置

示例：

```yaml
concurrency:
  io:
    core: 16
    max: 64
    queueSize: 10000
    keepAliveSeconds: 60
    threadNamePrefix: consilens-io-
  cpu:
    core: 8
    max: 16
    queueSize: 10000
    keepAliveSeconds: 60
    threadNamePrefix: consilens-cpu-
```

适用建议：

- IO 密集型场景：提高 `io.max`
- CPU 紧张机器：控制 `cpu.max`

## 五、输出配置（result.sinks）

输出通过 `result.sinks[]` 列表配置，每个条目对应一个 sink，可同时启用多个。

### 顶层字段

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `result.sinks` | 列表 | `[]` | sink 列表，顺序无关 |
| `result.parallelism` | 整数 | `4` | 保留字段，暂未启用 |
| `result.failOnSinkError` | 布尔 | `true` | sink 失败时是否中断主流程 |

每个 sink 的公共字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `format` | 是 | 输出格式：`table` / `json` / `jsonl` / `csv` / `console` |
| `type` | 是 | 数据类型：`diff-record`（差异明细）/ `result`（最终汇总） |
| `enabled` | 否 | 是否启用，默认 `true` |
| `properties` | 否 | 各 format 的专属扩展属性，YAML 嵌套对象 |

### console format

打印到标准输出，适合调试和本地运行。

```yaml
result:
  sinks:
    - format: console
      type: result
      properties:
        maxRows: 100
        showStatistics: true
```

`type: result` 时打印汇总统计；`type: diff-record` 时打印部分差异明细行（最多 `maxRows` 行）。

`console` 专属属性：

| 属性 | 默认值 | 说明 |
| --- | --- | --- |
| `maxRows` | `100` | 最多打印的差异明细行数，`-1` 表示不限制 |
| `showStatistics` | `true` | 是否打印统计汇总 |

### json format

将结果写出为 JSON 文件。

```yaml
result:
  sinks:
    - format: json
      type: diff-record
      properties:
        path: ./output/diff-${taskId}.json
        pretty: true

    - format: json
      type: result
      properties:
        path: ./output/summary-${taskId}.json
        pretty: false
```

`json` 专属属性：

| 属性 | 默认值 | 说明 |
| --- | --- | --- |
| `path` | 无 | 输出文件路径，支持 `${变量名}` 占位符 |
| `pretty` | `false` | 是否格式化输出（缩进） |
| `columns` | `[]` | 自定义字段映射列表（见下文），为空时序列化原始对象 |

**自定义字段示例（json diff-record）：**

```yaml
- format: json
  type: diff-record
  properties:
    path: ./output/diff-${taskId}.json
    pretty: true
    columns:
      - name: taskId
        value: ${taskId}
      - name: operation
        value: ${operation}
      - name: primaryKey
        value: ${primaryKey}
      - name: srcAmount
        value: ${src.amount}
        defaultValue: "0"
      - name: tgtAmount
        value: ${tgt.amount}
        defaultValue: "0"
      - name: env
        value: production
```

### jsonl format

每条差异记录写成一行 JSON（LF 结尾），适合流式处理，也是 `verify --baseline` 要求的基线格式。

```yaml
result:
  sinks:
    - format: jsonl
      type: diff-record
      properties:
        path: ./.consilens/baseline.jsonl
        maxRows: 100000
```

默认字段为 `operation` / `primaryKey` / `metadata`，`operation` 使用小写 code（`mismatch`、`source_missing`、`target_missing`）。`properties.columns` 支持与 `json` 相同的自定义字段映射。

后续可以用同一个文件做“只关注新差异”的 CI 门禁：

```bash
consilens-cli.sh verify -c compare.yaml --fail-on new --baseline .consilens/baseline.jsonl
```

`jsonl` 专属属性：

| 属性 | 默认值 | 说明 |
| --- | --- | --- |
| `path` | 无 | 输出文件路径，支持 `${变量名}` 占位符 |
| `maxRows` | 无限制 | 最多写入行数；超出后标记 truncated |
| `columns` | `[]` | 自定义字段映射列表，为空时写默认字段 |

### csv format

将差异明细写出为 CSV 文件。

```yaml
result:
  sinks:
    - format: csv
      type: diff-record
      properties:
        path: ./output/diff-${taskId}.csv
        delimiter: ","
        includeHeader: true
        columns:
          - operation
          - primaryKey
          - sourceValues
          - targetValues
```

`csv` 专属属性：

| 属性 | 默认值 | 说明 |
| --- | --- | --- |
| `path` | 无 | 输出文件路径，支持 `${变量名}` 占位符 |
| `delimiter` | `,` | 列分隔符 |
| `includeHeader` | `true` | 是否输出表头行 |
| `columns` | `[]` | 自定义字段映射列表（见下文），为空时输出默认 4 列 |
| `mergeDefaults` | `false` | 为 `true` 时保留默认列并用 `columns` 覆盖或追加 |

**自定义字段示例（csv diff-record）：**

```yaml
- format: csv
  type: diff-record
  properties:
    path: ./output/diff-${taskId}.csv
    columns:
      - name: task_id
        value: ${taskId}
      - name: op
        value: ${operation}
      - name: pk
        value: ${primaryKey}
      - name: src_amount
        value: ${src.amount}
        defaultValue: "0"
      - name: tgt_amount
        value: ${tgt.amount}
        defaultValue: "0"
      - name: env
        value: production
```

### table format

将差异明细或最终汇总写入数据库表。

```yaml
result:
  sinks:
    - format: table
      type: diff-record
      properties:
        url: jdbc:mysql://localhost:3306/consilens_results
        username: writer
        password: ${RESULT_DB_PASSWORD}
        driver: com.mysql.cj.jdbc.Driver
        maxPoolSize: 10
        prefix: diff_result_
        suffixTimestamp: true
        createTable: true
        dropIfExists: false
        defaultColumnLength: 500
        batchSize: 1000
```

`table` 专属属性：

| 属性 | 默认值 | 说明 |
| --- | --- | --- |
| `url` | 无 | JDBC URL |
| `username` | 无 | 数据库用户名 |
| `password` | 无 | 数据库密码 |
| `driver` | 自动推断 | JDBC 驱动类名 |
| `maxPoolSize` | `5` | 连接池最大连接数 |
| `tableName` | 无 | 显式表名；设置后忽略 `prefix` 和 `suffixTimestamp` |
| `prefix` | `diff_result_` | 表名前缀 |
| `suffixTimestamp` | `true` | 是否在表名后追加时间戳（`yyyyMMdd_HHmmss`） |
| `createTable` | `true` | 是否自动建表 |
| `dropIfExists` | `false` | 建表前是否先 DROP TABLE |
| `defaultColumnLength` | `255` | VARCHAR 列默认长度 |
| `batchSize` | `1000` | 批量写入行数 |
| `columns` | `[]` | 自定义字段映射列表（见下文），为空时使用默认宽表模式 |

**自定义字段示例（table diff-record）：**

```yaml
- format: table
  type: diff-record
  properties:
    url: jdbc:mysql://localhost:3306/mydb
    username: root
    password: secret
    tableName: my_diff_detail
    createTable: true
    columns:
      - name: task_id
        value: ${taskId}
      - name: diff_type
        value: ${operation}
      - name: pk_value
        value: ${primaryKey}
      - name: src_amount
        value: ${src.amount}
        defaultValue: "0"
        columnType: DECIMAL(18,2)
      - name: tgt_amount
        value: ${tgt.amount}
        defaultValue: "0"
        columnType: DECIMAL(18,2)
      - name: env
        value: production
      - name: created_at
        value: ${timestamp}
        columnType: TIMESTAMP
```

### fields 字段映射说明

`columns` 适用于 `table`、`csv`、`json` 三种 format。每个字段由以下属性组成：

| 属性 | 必填 | 说明 |
| --- | --- | --- |
| `name` | 是 | 输出列/字段名称 |
| `value` | 否 | 值模板，支持 `${变量名}` 占位符和纯静态字符串混合 |
| `defaultValue` | 否 | 兜底值，当 `value` 解析结果为空时使用 |
| `columnType` | 否 | SQL 列类型（仅 `table` format 建表 DDL 使用），未设置时默认 `TEXT` |

**内置变量（diff-record 类型）：**

| 变量 | 说明 |
| --- | --- |
| `${taskId}` | 任务 ID |
| `${sourceTable}` | 源表名 |
| `${targetTable}` | 目标表名 |
| `${strategy}` | 比对策略 |
| `${algorithm}` | 比对算法 |
| `${operation}` | 差异操作类型（SOURCE_MISSING / TARGET_MISSING / MISMATCH） |
| `${primaryKey}` | 主键字符串 |
| `${changedColumns}` | 变化列 JSON 数组（源端） |
| `${changedColumns1}` | 源端变化列 JSON 数组 |
| `${changedColumns2}` | 目标端变化列 JSON 数组 |
| `${src.列名}` | 源端指定列的值 |
| `${tgt.列名}` | 目标端指定列的值 |
| `${timestamp}` | 当前时间 ISO-8601 字符串 |
| `${attr.key}` | DiffContext 自定义属性 |

**内置变量（result 类型，除上述公共变量外）：**

| 变量 | 说明 |
| --- | --- |
| `${status}` | 执行状态（EQUAL / DIFF） |
| `${totalDifferences}` | 差异总数 |
| `${sourceMissingCount}` | 源端缺失行数 |
| `${targetMissingCount}` | 目标端缺失行数 |
| `${mismatchCount}` | 不一致行数 |
| `${sourceRowCount}` | 源端总行数 |
| `${targetRowCount}` | 目标端总行数 |
| `${statistics_json}` | 完整统计 JSON：`{"totalCount":N,"mismatchCount":N,"sourceMissingCount":N,"targetMissingCount":N,"totalDiffCount":N,"accuracyRate":N}`，其中 `accuracyRate = (totalCount - totalDiffCount) / totalCount * 100`，保留 2 位小数（可为负数） |

### 同一 format+type 多个 sink

同一 `format` + `type` 组合可以配置多个 sink 条目，各 sink 独立运行，输出到不同的表或文件。

### 部分列覆盖（mergeDefaults）

diff-record 类型支持 `mergeDefaults: true`，保留所有默认输出列，仅对 `columns` 中匹配名称的列进行值替换，不匹配的列继续使用默认值。CSV/JSON 格式还会将 `columns` 中不属于默认列的额外列追加到末尾。

```yaml
result:
  sinks:
    # 默认宽表，仅覆盖 nl_dq_execution_id 的值来源
    - format: table
      type: diff-record
      properties:
        url: jdbc:mysql://localhost:3306/db
        username: root
        password: secret
        tableName: diff_detail
        mergeDefaults: true
        columns:
          - name: nl_dq_execution_id
            value: ${attr.customId}   # 覆盖默认 taskId 来源
    # CSV：默认 4 列 + 覆盖 operation + 追加自定义列
    - format: csv
      type: diff-record
      properties:
        path: ./output/diff-${taskId}.csv
        mergeDefaults: true
        columns:
```

## 六、标准化配置

标准化配置对应：

- [NormalizationConfig.java](../consilens-cli/src/main/java/com/consilens/cli/model/normalization/NormalizationConfig.java)
- [TypeNormalizationRule.java](../consilens-cli/src/main/java/com/consilens/cli/model/normalization/TypeNormalizationRule.java)

支持层级：

- `global`
- `source`
- `target`
- `columns`（列级；当前只开放数值容差）

优先级：

- 数据源侧覆盖全局配置
- 列级容差覆盖类型级容差

示例：

```yaml
normalization:
  global:
    decimal:
      precision: 2
      rounding: true
    timestamp:
      format: yyyy-MM-dd HH:mm:ss
      timezone: UTC
    float:
      # 数值容差：绝对/相对任一满足即判等
      tolerance: 0.01
      relativeTolerance: 0.001
  source:
    binary:
      encoding: hex
      uppercase: false
  target:
    boolean:
      trueValue: "1"
      falseValue: "0"
      nullValue: ""
  columns:
    price:
      # 列级容差覆盖类型级；当前列级只支持 tolerance/relativeTolerance
      tolerance: 0.5
      relativeTolerance: 0.0001
```

当前版本说明：

- 支持按数据类型配置（decimal 精度/舍入、日期格式/时区、字符串 trim/null、布尔映射、二进制编码）。
- 支持按列配置**数值容差**（`tolerance` / `relativeTolerance`）；列级精度/时区需要方言 SQL 侧同步实现，当前会被 validator 拒绝，避免“本地生效、校验和不生效”的口径分叉。
- 容差在**终局本地比较**生效：checksum 路径会先把差异段收敛到本地逐行比较，再按容差判等；`row-hash` 候选回查同样生效。
  SQL 侧哈希表达不了容差（值不同哈希必不同），所以配了容差的列一定会走终局比较，而不是"SQL 判等就跳过"。
- **容差内的行怎么记账**由 `normalization.tolerance` 决定（默认不算差异，但报告里单独列出）：

  ```yaml
  normalization:
    tolerance:
      withinTolerance: ignore   # ignore（默认）| report
      reportSamples: 100        # 报告里最多列多少条样本；0 = 只给计数不列行
  ```

  - `ignore`：判等，**不计入** `totalDifferences`，不落差异 sink；统计里给出
    `withinToleranceCount`，console 结果多一个 `withinTolerance` 块（含样本行与差值），
    CSV 的 diff-record sink 另写一个 `<文件名>.within-tolerance.csv`（**该文件名是保留名**，
    每次运行会先清掉上一轮的同名文件；内容是样本，最多 `reportSamples` 条，不是全集），
    `verify` 的 Markdown 报告有「容差内（未计入差异）」一节。
  - `report`：审计档，容差内仍然**算差异**（旧口径），同时 `withinToleranceCount` 仍会统计出
    有多少行属于"容差吸收"，便于核对容差是否配得过宽。这些行已经出现在差异列表里，所以
    `withinTolerance` 块只给 `count`（`rows` 为空），也不会生成 `<文件名>.within-tolerance.csv`，
    避免同一行列两遍。
  - `reportSamples` 上限 10000（超过直接报错），0 表示只给计数不列行。

- 局限：streaming（有序合并）与 join 路径按规范化后的值/SQL 比较，**不应用容差**；需要容差的列请使用 checksum 策略，或把容差列排除后单独核对。
- 整数列始终精确比较；容差只作用于 FLOAT/DOUBLE/REAL 等浮点列。同一浮点列的两种文本渲染
  （如 `10.5` 与 `10.500`）不算"容差内差异"，不会出现在样本里。

## 七、终局比较说明

默认无需额外配置，终局小段会使用 `full` 模式直接拉完整行比较。

如果确认当前场景适合先用行哈希过滤，可以显式配置：

```yaml
strategy:
  localCompare:
    mode: row-hash
```
