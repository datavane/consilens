# 集群提交指南（YARN / Kubernetes）

## 适用对象

本文面向需要把数据比对作业提交到 YARN 或 Kubernetes 集群执行的用户。设计目标沿用 spark-submit
的使用习惯：**一个能提交 Spark 应用的环境，不需要额外改造就能提交 Consilens**。本文假定你熟悉
spark-submit 或 flink 的基本概念（master、queue、staging、LocalResource、ConfigMap 等）。

相关文档：[快速开始](01-快速开始.md)、[配置详解](02-配置详解.md)。

## 总览

Consilens 提供三个执行后端，统一由 `consilens submit` 入口进入：

```bash
consilens submit local        # 本地模拟执行，生成 manifest，不起集群进程
consilens submit yarn         # 提交到 YARN 集群，以 ApplicationMaster 方式运行
consilens submit kubernetes   # 提交到 Kubernetes，以 Job 方式运行
```

两个集群后端共享同一套抽象：

- **descriptor（比对描述）**是唯一的应用资源，像 spark-submit 的应用 jar 一样作为位置参数传入；
  它在提交侧只被解析引用、不解析内容，凭据通过 `${env.NAME}` 占位符在执行节点上解析，
  因此**提交机不需要任何数据源凭据**。
- **默认等待**：客户端提交后阻塞到应用结束，输出最终状态，行为与 `spark-submit --master yarn`
  的 cluster 模式一致。
- **三层配置**：CLI 选项 > `--conf` / `--properties-file` > 内置默认值，与 spark-defaults.conf
  的分层方式一致。

提交链路架构：

```
YARN:       CLI ──YarnClient──▶ ResourceManager
                 │                  │
                 │ staging 上传      ▼
                 ├──────────▶ AM 容器（本地化 runtime/conf/descriptor/files）
                 │                  │ ConsilensApplicationMaster
                 │                  ├─ 注册 RM + 心跳（AMRMClient）
                 │                  └─ 反射拉起 ClusterComparisonCoordinator
                 │                        └─ 比对 ──▶ stdout 摘要 JSON
                 ◀── 轮询 finalStatus（SUCCEEDED / FAILED）──┘

Kubernetes: CLI ──Fabric8──▶ API Server
                 │                │
                 │ descriptor     ▼
                 ├─ConfigMap──▶ Job ──▶ Pod（镜像内含 runtime）
                 │                    └─ java -cp /opt/consilens/runtime/* Coordinator
                 ◀── 轮询 Job 条件（Complete / Failed）──┘
```

## YARN 提交

### 快速开始

```bash
# 1. 一次性上传 runtime archive（等价 spark.yarn.archive 的运维方式）
hdfs dfs -put -f consilens-cluster-application-0.1-SNAPSHOT-runtime.zip /apps/consilens/runtime.zip

# 2. 可选：写一份 spark-defaults.conf 风格的默认值文件
cat > consilens-defaults.conf <<'EOF'
consilens.yarn.archive=hdfs:///apps/consilens/runtime.zip
consilens.yarn.queue=default
consilens.yarn.am-memory=1g
consilens.yarn.am-vcores=1
consilens.yarn.maxAppAttempts=-1
EOF

# 3. 日常提交：descriptor 与密钥文件作为位置参数
consilens submit yarn \
  --properties-file consilens-defaults.conf \
  comparison.yaml

# 输出：
# YARN application submitted: application_1789255918989_0003
# YARN application finished: application_1789255918989_0003 finalStatus=SUCCEEDED trackingUrl=http://rm:8088/proxy/...
```

### 环境要求

| 要求 | 说明 | 与 Spark 的对应 |
|---|---|---|
| `HADOOP_CONF_DIR` 可用 | 客户端读取 yarn-site.xml/core-site.xml 连接 RM；该目录还会整体打进 AM 容器 | 同 spark-submit 的要求，路径一致 |
| 提交机能直连 RM RPC 端口 | 如 8032 | 同 |
| AM 容器有 Java 11 的 `JAVA_HOME` | runtime 按 Java 11 编译；由集群管理员通过 `yarn.nodemanager.admin-env` 或镜像提供 | Spark 对容器 JAVA_HOME 的要求方式相同 |
| HDFS 可写 | staging 使用用户 HDFS home | 同 |

`yarn.nodemanager.admin-env` 配置示例（Java 8 服务进程不受影响，只影响 YARN 容器负载）：

```xml
<property>
  <name>yarn.nodemanager.admin-env</name>
  <value>JAVA_HOME=/opt/jdk11</value>
</property>
```

### 位置参数

```
consilens submit yarn [options] <descriptor> [<secret-env-file>]
```

| 位置 | 说明 |
|---|---|
| `<descriptor>` | 比对描述文件（本地路径或 HDFS/远端 URI），等价 spark-submit 的应用 jar。数据源用户名/密码直接写在 descriptor 的 connection 里，随提交上传到用户的 staging 目录（生产环境建议开启 HDFS 权限并限制 staging 目录访问） |

### CLI 选项

| 选项 | 默认值 | 说明 |
|---|---|---|
| `--runtime-archive <path\|uri>` | 无（可由 conf 提供） | runtime archive；接受 `*-runtime.zip`（按 ARCHIVE 解压为 `consilens-runtime/*`）或单个 fat jar（按 FILE 加载为 `consilens-runtime.jar`），按扩展名自动选择 |
| `--queue <queue>` | `default` | YARN 队列 |
| `--name <name>` | `consilens-<submissionId>` | 应用名 |
| `--am-memory <1g\|2048m>` | `1g` | AM 容器内存，Spark 内存格式 |
| `--am-vcores <n>` | `1` | AM 容器虚拟核数 |
| `--files <a,b#c,...>` | 无 | 随提交上传的文件，AM 容器内按文件名（或 `#alias`）可见，语义同 spark `--files` |
| `--jars <a.jar,b.jar>` | 无 | 随提交上传的 jar，追加到 AM classpath（排在 runtime 之后），语义同 spark `--jars` |
| `--properties-file <file>` | 无 | `consilens.yarn.*` 默认值文件 |
| `--conf key=value` | 无 | 单条覆盖，可重复 |
| `-c, --config <file>` | 无 | 兼容旧脚本的保留参数，提交时不读取 |

### 配置键（`consilens.yarn.*`）

`--conf` 与 `--properties-file` 使用同一命名空间，键名对齐 `spark.yarn.*`：

| 键 | 默认值 | 说明 | Spark 对应 |
|---|---|---|---|
| `consilens.yarn.archive` | 无 | runtime archive 位置，推荐预传 HDFS 后在此固定 | `spark.yarn.archive` |
| `consilens.yarn.stagingDir` | `<HDFS home>/.consilens/staging` | staging 根目录 | `spark.yarn.stagingDir` |
| `consilens.yarn.maxAppAttempts` | `-1`（跟随集群默认） | 最大尝试次数；`-1` 表示使用 RM 的 `yarn.resourcemanager.am.max-attempts` | `spark.yarn.maxAppAttempts` |
| `consilens.yarn.queue` | `default` | 队列 | `--queue` |
| `consilens.yarn.name` | `consilens-<submissionId>` | 应用名 | `spark.app.name` |
| `consilens.yarn.amMemory` | `1g` | AM 内存 | `spark.yarn.am.memory` |
| `consilens.yarn.amVCores` | `1` | AM vcores | `spark.yarn.am.cores` |
| `consilens.yarn.files` | 无 | 同 `--files` | `spark.files` |
| `consilens.yarn.jars` | 无 | 同 `--jars` | `spark.jars` |
| `consilens.yarn.tags` | 无 | 逗号分隔的 YARN application tags | `spark.yarn.tags` |
| `consilens.yarn.submit.waitAppCompletion` | `true` | 提交后是否阻塞等待结束 | `spark.yarn.submit.waitAppCompletion` |

优先级：CLI 选项 > `--conf` > `--properties-file` > 内置默认值。

### 提交行为详解

**staging**：本地 artifact（runtime、descriptor、secret、`--files`/`--jars` 中的本地项）上传到
`<stagingDir>/<submissionId>/`，文件保留原名；全部为远端 URI 时不触碰 staging。应用**成功**结束后
由 AM 自动删除该目录（失败时保留以便排查，可用 `--conf consilens.yarn.stagingDir=...` 自定义位置）。

**Hadoop conf 本地化**：提交机的 `HADOOP_CONF_DIR`（或 classpath 上的 `yarn-site.xml`）中的每个文件
作为 `hadoop-conf/<file>` LocalResource 打进 AM 容器并加入 classpath——与 Spark 的 `__spark_conf__`
机制相同。因此 AM 与提交端看到完全一致的 RM 地址；缺失时提交直接报错。

**AM 进程**：AM 命令为

```
$JAVA_HOME/bin/java -server -Xmx1024m -cp "$PWD:hadoop-conf:consilens-runtime/*" \
  com.consilens.cluster.application.ConsilensApplicationMaster \
  --coordinator-class com.consilens.cluster.application.ClusterComparisonCoordinator \
  --descriptor submission-descriptor.yaml --secrets submission-secrets.properties \
  --staging-dir <staging>/<submissionId>
```

`ConsilensApplicationMaster` 是固定的包装类（对齐 `org.apache.spark.deploy.yarn.ApplicationMaster`
包装用户 driver 的模型）：注册 RM、每 5 秒 allocate 心跳、反射拉起 coordinator main；
coordinator 正常返回上报 `SUCCEEDED`；coordinator 抛异常或非零退出（`System.exit`）上报 `FAILED`，
diagnostics 带失败原因（类名 + 消息）。

> 限制（2026-10）：AM 当前只接受 `--coordinator-class` / `--descriptor` / `--staging-dir`，
> `--secrets` 会被接受但忽略（凭据需通过环境变量注入）。

**比对结果**：AM 会把 coordinator 打印的摘要 JSON（最后一行 `{"submissionId":...,"statistics":{...}}`）
写入 RM diagnostics；YARN 提交端通过 `ApplicationReport.getDiagnostics()` 取回，服务端据此还原
source/target 行数与差异数（差异**明细**仍在容器日志里，通过 `yarn logs -applicationId <appId>` 查看）。
diagnostics 由 RM 存储，过长会被截断；摘要超过 4000 字符时 AM 会截断，服务端解析失败则退化为
`statisticsUnavailable=true`（Kubernetes 提交暂未回传摘要）：

```json
{"submissionId":"...","statistics":{"sourceRowCount":10001,"targetRowCount":10000,
 "mismatchCount":1,"targetMissingCount":1,"totalDifferences":2,...}}
```

**失败排查**：

```bash
yarn logs -applicationId <appId>                                  # AM/容器日志
curl http://rm:8088/ws/v1/cluster/apps/<appId>                    # diagnostics 字段
CONSILENS_DEBUG=1 consilens submit yarn ...                       # 提交侧打印完整异常栈
```

提交失败默认只输出异常类名（异常消息可能包含连接凭据）；参数校验类错误输出完整消息。

## Kubernetes 提交

### 快速开始

```bash
# 1. 构建包含 runtime 的镜像（runtime 固定放在 /opt/consilens/runtime/）
docker build -f deploy/cluster/Dockerfile -t registry.example/consilens-runtime:0.1.0 .

# 2. 提交：descriptor 位置参数（本地文件自动转 ConfigMap）
consilens submit kubernetes \
  --image registry.example/consilens-runtime:0.1.0 \
  --memory 1g --cpu 0.5 \
  --env MYSQL_USER=root --secret-env MYSQL_PASSWORD=consilens-database/source-password \
  comparison.yaml

# 输出：
# Kubernetes Job submitted: default/consilens-<submissionId>
# Kubernetes Job finished: default/consilens-<submissionId> finalStatus=SUCCEEDED
```

### 环境要求

| 要求 | 说明 | 与 Spark/Flink on K8s 的对应 |
|---|---|---|
| kubeconfig 可用 | `~/.kube/config` / `KUBECONFIG` / in-cluster，走 Fabric8 标准发现链 | 同 spark-on-k8s 客户端 |
| 镜像内含 runtime | `/opt/consilens/runtime/consilens-cluster-application.jar`，Java 11 基础镜像 | spark-on-k8s 要求 runtime 在镜像内；**没有本地 jar 上传通道** |
| Namespace 存在 | 默认 `default` | 同 |
| Secret（如使用 `--secret-env`） | 预先创建于同 namespace | 同 spark.kubernetes.driver.secrets 用法 |

### 位置参数与 descriptor 来源

```
consilens submit kubernetes [options] <descriptor>
```

descriptor 的两种来源（同 Flink 用 ConfigMap 承载配置的做法）：

| 形式 | 行为 |
|---|---|
| 本地路径（位置参数或 `--descriptor-uri` 传本地路径） | 内容读取后写入 ConfigMap `<jobName>-descriptor`，挂载到容器 `/opt/consilens/descriptor/`，只读；ConfigMap 名可用 `--descriptor-config-map` 覆盖 |
| HTTP(S) URI | 原样传给 coordinator，由 Pod 运行时拉取 |

带 URI scheme 的位置参数（如 `https://...`）自动识别为远端形式，与 Spark 接受远端应用资源的方式一致。
安全约束：服务端生成 descriptor 时会把明文 `password` 替换为 `${env.<SIDE>_PASSWORD}`，并校验对应的 `--secret-env` 已提供，否则提交直接失败——明文密码不会进入 ConfigMap/Pod 环境。

### CLI 选项

| 选项 | 默认值 | 说明 |
|---|---|---|
| `--image <image>` | 必填 | 含 runtime 的容器镜像 |
| `--namespace <ns>` | `default` | 目标 namespace |
| `--name <name>` | `consilens-<submissionId>` | Job 名 |
| `--memory <1g\|2048m>` | `1g` | Pod 内存（requests=limits） |
| `--cpu <0.5\|1>` | `0.5` | Pod CPU 核心数 |
| `--env KEY=value` | 无 | 普通环境变量，可重复（`spark.kubernetes.driver.env.[KEY]` 对应） |
| `--secret-env ENV=secret/key` | 无 | 环境变量绑定 Secret 键，可重复 |
| `--image-pull-policy <p>` | `IfNotPresent` | Always / IfNotPresent / Never |
| `--image-pull-secret <name>` | 无 | 镜像拉取凭据，可重复（`spark.kubernetes.imagePullSecrets` 对应） |
| `--service-account <name>` | 无 | Pod service account |
| `--label key=value` | 无 | 额外标签，可重复；自动附加 `app.kubernetes.io/name=consilens` |
| `--max-attempts <n>` | `1` | Job 总尝试上限，映射为 `backoffLimit=n-1` |
| `--descriptor-uri <uri>` | 无 | 位置参数的显式形式，二者互斥 |
| `--descriptor-config-map <name>` | `<job>-descriptor` | 本地 descriptor 的 ConfigMap 名 |
| `--properties-file <file>` | 无 | `consilens.kubernetes.*` 默认值文件 |
| `--conf key=value` | 无 | 单条覆盖，可重复 |

### 配置键（`consilens.kubernetes.*`）

| 键 | 默认值 | 说明 |
|---|---|---|
| `consilens.kubernetes.image` | 无 | 容器镜像 |
| `consilens.kubernetes.namespace` | `default` | namespace |
| `consilens.kubernetes.name` | `consilens-<submissionId>` | Job 名 |
| `consilens.kubernetes.memory` | `1g` | 内存 |
| `consilens.kubernetes.cpu` | `0.5` | CPU 核心数 |
| `consilens.kubernetes.serviceAccount` | 无 | service account |
| `consilens.kubernetes.imagePullPolicy` | `IfNotPresent` | 拉取策略 |
| `consilens.kubernetes.imagePullSecrets` | 无 | 逗号分隔的拉取凭据 |
| `consilens.kubernetes.submit.waitAppCompletion` | `true` | 是否阻塞等待结束 |

优先级同 YARN：CLI 选项 > `--conf` > `--properties-file` > 内置默认值。

### Job 行为详解

**资源模型**：单 Pod Kubernetes Job（`restartPolicy: Never`），一次比对一个 Job——这是 Flink
Application Mode（常驻 Deployment + HA）与 Spark Driver Pod 之间对"一次性批处理"的正确选择。
重试由 `backoffLimit=maxAttempts-1` 控制，重试时 descriptor ConfigMap 复用，无需重复提交。

**凭据注入**：`--env` 以普通 envVar 注入；`--secret-env` 以 `secretKeyRef` 注入（值不落盘在
Job spec 之外的任何地方，`kubectl get job -o yaml` 只能看到 Secret 引用）。

**等待与结果**：客户端轮询 Job 的 `Complete`/`Failed` condition（每 3 秒），结束时输出
finalStatus。比对摘要 JSON 在 coordinator stdout：`kubectl logs job/<name>`。

**失败排查**：

```bash
kubectl describe job <name>       # 事件、backoff、pod 状态
kubectl logs job/<name>           # coordinator 日志与摘要 JSON
kubectl get configmap <job>-descriptor -o yaml   # 提交的 descriptor（已脱敏）
CONSILENS_DEBUG=1 consilens submit kubernetes ...
```

## 常见问题

**Q：runtime jar 每次提交都要上传吗？**
YARN：不需要。预传 HDFS 一次，在 `consilens.yarn.archive` 固定引用即可（同 `spark.yarn.archive`）。
Kubernetes：runtime 在镜像里，升级 runtime = 发布新镜像 tag。

**Q：怎么加自定义 JDBC 驱动？**
YARN：`--jars ./ojdbc8.jar`（进 AM classpath）。
Kubernetes：把驱动打进镜像（标准做法）；小文件也可以放 descriptor 同目录用 `--env` 指路径。

**Q：密码写在哪里？**
YARN：直接写在 descriptor 的 connection 中，随提交上传到用户 staging（同 Spark 把配置文件
放进应用 jar/`--files` 的惯例）；生产环境开启 HDFS 权限并限制 staging 目录访问。
K8s：简单场景同样直接写在 descriptor（随 ConfigMap 下发）；已有 K8s Secret 管理的场景用
`--secret-env ENV=secret-name/key` 以 secretKeyRef 注入（对齐 Spark 的
`spark.kubernetes.driver.secretKeyRef.ENV_NAME`）。

**Q：`--files` 上传的文件在容器里哪里能找到？**
AM 容器的工作目录（`$PWD`），按原文件名或 `#alias` 命名，descriptor 中直接写该相对路径即可。

**Q：怎么关闭提交后等待？**
YARN：`--conf consilens.yarn.submit.waitAppCompletion=false`；
K8s：`--conf consilens.kubernetes.submit.waitAppCompletion=false`。之后可用
`yarn logs` / RM UI 或 `kubectl logs job/<name>` 自行跟踪。

**Q：为什么没有 `--master` / `--deploy-mode`？**
后端由子命令（`submit yarn` / `submit kubernetes`）决定，且比对作业没有 driver/executor 分角色，
这两个 Spark 选项对 Consilens 没有对应的语义。
